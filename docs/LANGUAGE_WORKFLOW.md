# KYNZA — Add a New Language in Under 5 Minutes

Adding a language to KYNZA requires exactly 5 steps. No other code changes
are needed — the `AppLanguage.values` iteration handles everything automatically.

---

## Prerequisites

- Flutter SDK installed (`flutter gen-l10n` must be available)
- Access to the Supabase dashboard or migration tooling
- A translated ARB file (copy `app_fr.arb`, translate the values)

---

## Step 1 — Add an entry in `AppLanguage`

File: `lib/core/localization/models/language_enum.dart`

```dart
enum AppLanguage {
  french(
    code: 'fr',
    countryCode: null,
    nativeName: 'Français',
    englishName: 'French',
    flagEmoji: '🇫🇷',
    isRtl: false,
  ),
  english(
    code: 'en',
    countryCode: null,
    nativeName: 'English',
    englishName: 'English',
    flagEmoji: '🇬🇧',
    isRtl: false,
  ),
  // Add your language here:
  kirundi(
    code: 'rn',
    countryCode: null,
    nativeName: 'Kirundi',
    englishName: 'Kirundi',
    flagEmoji: '🇧🇮',
    isRtl: false,
  );
  // ...
}
```

Fields:
- `code`: ISO 639-1 or 639-3 language code (used as Hive key and `Locale` code)
- `countryCode`: `null` unless a country-specific variant is needed (e.g. `'BI'` for `fr_BI`)
- `nativeName`: displayed in the language picker
- `englishName`: displayed as subtitle in the language picker
- `flagEmoji`: country flag emoji (UI only)
- `isRtl`: `true` for Arabic, Hebrew, etc. — `false` for all current languages

The `LanguageSettingsScreen` renders `AppLanguage.values` automatically. No UI
change is needed.

---

## Step 2 — Create the ARB translation file

File: `lib/l10n/app_[code].arb` (e.g. `lib/l10n/app_rn.arb` for Kirundi)

```bash
# Start from the French file (canonical source of keys)
cp lib/l10n/app_fr.arb lib/l10n/app_rn.arb
```

Edit the new file:
1. Change `"@@locale": "fr"` to `"@@locale": "rn"`.
2. Translate every string value. Do not change keys, `@` metadata blocks, or
   placeholder names.
3. Keep `"appName": "KYNZA"` untranslated — brand name is never localised.
4. Keep BIF amounts as-is; they are handled by `CurrencyFormatter`, not ARB.

Example (partial):

```json
{
  "@@locale": "rn",

  "appName": "KYNZA",
  "@appName": { "description": "Nom de l'application — ne jamais traduire" },

  "commonCancel": "Kureka",
  "commonConfirm": "Kwemeza",
  "commonSave": "Kubika",
  ...
}
```

## Step 3 — Add the language code to Supabase

The `users.preferred_language` column has a CHECK constraint that allowlists
supported language codes. Add your new code to it via a migration:

```sql
-- supabase/migrations/<timestamp>_add_language_rn.sql

ALTER TABLE public.users
  DROP CONSTRAINT IF EXISTS users_preferred_language_check;

ALTER TABLE public.users
  ADD CONSTRAINT users_preferred_language_check
  CHECK (preferred_language IN ('fr', 'en', 'rn'));
```

Apply with:

```bash
supabase db push
```

This prevents the backend from storing an invalid language code when
`LanguageNotifier.setLanguage()` syncs the preference to Supabase.

---

## Step 4 — Regenerate, analyse, test

```bash
# 1. Regenerate localisation classes from ARB files
flutter gen-l10n

# 2. Static analysis (must be 0 issues)
flutter analyze

# 3. Full test suite (must be all green)
flutter test
```

`flutter gen-l10n` will fail with a clear error if any key is missing from the
new ARB file, or if a placeholder type is inconsistent across locales.

---

## Step 5 — Verify ARB parity

```bash
flutter test test/core/localization/l10n_coverage_test.dart
```

This test suite checks that common, auth, offline, and settings keys are
non-empty in all loaded locales. If new critical key groups were added since
the last language was introduced, add matching test cases to keep coverage
current.

---

## What does NOT need to change

- `LanguageSettingsScreen` — iterates `AppLanguage.values` automatically
- `LocaleDetectionService` — calls `AppLanguage.fromCode()` which covers any
  new entry
- `MaterialApp` — `AppLocalizations.supportedLocales` is regenerated by
  `flutter gen-l10n`
- `currentLocaleProvider` / `LanguageNotifier` — generic over language codes
- Router, guards, RLS policies — language is presentation-only

| **Total** | ~25–30 min per language |
